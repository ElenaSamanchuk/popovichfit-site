## Сопоставление с исходниками

SVG используется ровно двумя элементами блока `rec1571472611` в `app/data/tilda/page38609605.json`:

| Элемент | Брейкпоинт 640: left / top / width | Расчёт X при окне 768 | Брейкпоинт 320: left / top |
|---|---|---|---|
| `1762957642971` | grid 2351 / −302 / 25 | 768 / 2 − 320 + 2351 = **2415 px** | 275 / 123 |
| `176295770155947430` | grid 2355 / −380 / 25 | 768 / 2 − 320 + 2355 = **2419 px** | 121 / 123 |

1. На 768 действует диапазон 640–959.98 из `app/utils/tilda-css.ts`. У этого блока `upscale=grid`, поэтому применяется центрирование сетки, без масштабирования 640 → 768
2. Обе картинки находятся за правым краем окна и выше собственного артборда. `ZeroBlock.vue` задаёт артборду `overflow-hidden`, `ZeroElem.vue` — изображениям `loading=lazy`. Отсутствие загрузки невидимой lazy-картинки само по себе не является поломкой
3. Координаты совпадают с атрибутами элементов в локальном исходном экспорте `old-site/page38609605.html`; на мобильном брейкпоинте эти иконки возвращаются внутрь карточек. Удалять их или переносить на планшете по догадке нельзя
4. SVG существует в `public/img/t/` и в просмотренной `.output/public/img/t/`; XML успешно разобран, объявлены width/height 31 и viewBox `0 0 31 31`. Файлы побайтно совпадают: SHA-256 `9c752934a63fde5f92b64b78f0a59992f9b52d20810275cc8fd8b8c5ca25c2f4`. Это проверка файлов, не HTTP-ответа
5. В просмотренном `.output/public/taplink/index.html` присутствуют те же CSS-координаты и обе lazy-картинки. Сборка не запускалась; принадлежность этого файла именно историческому прогону не доказана
6. Текущий `scripts/verify-priority.mjs` уже проверяет видимость условием `r.left < document.documentElement.clientWidth` перед включением в `broken`. Его фактическая функция `vis` отдельно исполнена с расчётными координатами обеих иконок: оба результата **false**, обе проверки assertion прошли. Это статическая проверка предиката с модельными DOM-прямоугольниками, не воспроизведение в браузере

## Решение и границы

**Ничего не исправлять сейчас.** В текущем тесте уже есть фильтр, исключающий эти координаты; оснований повторять правку, делать картинки eager, менять CSS или удалять элементы нет. Во время чтения тест правился параллельно другим исполнителем, поэтому строки/хэши файла могут меняться; в этой подзадаче он не редактировался.

Старый лог не содержит `complete`, `naturalWidth`, DOM-прямоугольников, computed styles или хэша версии скрипта. Нельзя доказать, был ли это прежний фильтр, промежуточное состояние разметки или иной сбой. Статус: **дефект страницы не подтверждён; историческое падение требует узкого ретеста для окончательного закрытия**.

## Следующий шаг только после согласования сервера

Существующий автономный тест позволяет сузить запуск, без нового тестового набора и без повторного build:

```sh
nice -n 15 node scripts/verify-priority.mjs --base http://127.0.0.1:<согласованный-порт> --pages /taplink --widths 768 --out docs/screens/2026-11-09-final/taplink-768-retest-Codex.json
```

Команда здесь **не запускалась**. После подтверждения актуальности сборки выполнить два последовательных прогона в разные выходные файлы. Если падение повторится, сохранить скриншот 768, id элементов, `complete`, `naturalWidth`, `getBoundingClientRect()`, вычисленные стили и сетевой результат SVG; затем решать вопрос о точечном исправлении. Не запускать команду без `--base`: по умолчанию она сама поднимает сервер.
